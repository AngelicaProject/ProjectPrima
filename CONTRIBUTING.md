# Участие в переводе

## С чего начать

1. Сделайте форк репозитория.
2. Установите [Aeria](https://github.com/AngelicaProject/Aeria/releases) и
   клонируйте **свой форк** из её стартового окна (Clone project,
   `https://github.com/<ваш-логин>/ProjectPrima.git`). Нужна установленная
   игра той же версии, что указана в `aeria.json`.

## Как отправить правку

1. Обновите форк: на странице форка на GitHub нажмите Sync fork, затем в
   Aeria на ветке `main` выполните Pull.
2. Создайте от `main` новую ветку в списке веток Git-панели Aeria. В `main` своего форка не коммитьте: она нужна, чтобы
   получать изменения проекта.
3. Переводите и правьте в редакторе.
4. Сделайте коммит (Commit) и Push: ветка появится в вашем форке.
5. На GitHub откройте pull request из этой ветки форка в `main` этого
   репозитория и опишите, что изменено.
6. Замечания по pull request исправляйте в той же ветке: новый коммит и Push
   сразу попадают в pull request.

Каждый pull request проверяет Aeria Guard: проект читается, переводы
проходят проверки Aeria, а текст игры (`msgid`, комментарии с текстом игры,
набор строк и файлов) не изменён. Если проверка не прошла, откройте её во
вкладке Checks pull request: ошибки отмечены на строках файлов. В сводке
проверки собраны изменённые строки — с ней удобно проверять pull request.

Если `main` проекта ушёл вперёд и GitHub сообщает о конфликте, не разрешайте
его кнопками GitHub: в PO-файлы попадут маркеры конфликта. Напишите об этом в
pull request — конфликт разрешит сопровождающий, — или обновите форк и
перенесите правки в новую ветку от свежего `main`.

После merge ветку можно удалить в списке веток Aeria вместе с её копией в
форке.

Мелкие правки можно присылать в issue со ссылкой на строку
(`msgctxt` из PO-файла или скриншот из игры).

## Для сопровождающих

В `main` попадают только pull request, прошедшие Aeria Guard: прямой push и
force-push в `main` запрещены всем, включая сопровождающих. Работайте в
ветке этого репозитория: создайте её в Aeria, отправьте (Push) и нажмите
Pull request в Git-панели. Если коммиты уже сделаны в `main` и Push
отклонён, создайте ветку на текущем коммите — коммиты перейдут в неё.

Обновление проекта до новой версии игры делается в Aeria и тоже приходит
через pull request; Aeria Guard отметит смену версии игры, а текст игры в
нём не сверяет. Pull request сливается кнопкой Merge (merge-коммит):
история веток нужна Aeria для слияния переводов по строкам.

Теги релизов пака `harmonia/*` создают только сопровождающие, и их нельзя
перенести или удалить.

## Правила

- Стиль и термины — по `aeria-knowledge/`. Решение, которое меняет стиль
  или термин для всего проекта, обсуждается в issue до правок.
- Не переносите в перевод тексты из других переводов и источников, права на
  которые вам не принадлежат.
- Не правьте `msgid` и комментарии с текстом игры: они приходят из игры и
  обновляются Aeria при выходе патча.
